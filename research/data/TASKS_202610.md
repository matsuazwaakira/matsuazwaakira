# 追加調査・営業メモ作成の手順（2026-10, 令和8年度）

共通:
- WebSearch（ToolSearch "select:WebSearch" で読み込み）。自治体サイトへの WebFetch はブロックされがち（1〜2回試して無理ならやめる）。検索上限は1セッション200回（サブエージェント合算）なので配分すること。
- 期間などは検索結果の本文で確認できたものだけ「確認済」。要約1回のみ・推測は「推定」。URLは検索結果に出たものだけ（作らない）。
- 似た名前の他県自治体と混同しない。
- 結果は指定の出力ファイル（新規）だけに書き、そのファイルだけをコミットしてブランチ claude/epic-davinci-sky0yc に push（拒否されたら git pull --rebase して再 push、最大4回）。既存の JSON は編集しない。途中でもこまめに保存・push。
- 最後に要点を短く報告。

## 調査タスク（tasks_A/B/C/D.json）
各レコードの task 欄の作業をする。current は現在のデータ（参考）。
出力: patch_<A|B|C|D>.json — 配列。各要素:
{"pref","name","task",
 "set": { 更新したいフィールドだけ: t_name,t_period,t_end(令和年度の整数),t_conf(確認済|推定|不明),t_status(未確認|着手済|策定済|計画なし),t_url, e_name,e_period,e_end,e_conf,e_status,e_url },
 "note_add": "追記する注釈（根拠・次期計画の着手状況・日付・URL）",
 "evidence_quote": "期間の根拠となる本文の短い引用"}
- task1: 国交省「地域公共交通計画の作成状況一覧」(R8.5末)に計画ありと載っている自治体。市町村独自計画（または広域計画）を特定し、計画名・期間・URL・次期計画の着手状況を埋める。
- task2: 終期R9が「推定」の計画。本文で期間を確定（確認済にする）か、別の期間ならその値に直す。
- task3: 環境基本計画を特定（名称・期間・URL）。無いと判断できる根拠（例: 町の計画一覧に無い、区域施策編のみ）があれば e_status=計画なし とし note_add に根拠。終期R8〜R9のものは次期計画の着手状況も調べる。
- status の意味: 着手済=次期計画の策定業務委託・パブコメ等を確認（新計画は未策定）、策定済=記載の計画自体がR7〜R8に策定された新計画。

## 営業メモ（memo_targets_E/F.json）
対象は終期R9の計画を持つ自治体（営業対象）。各自治体について調べる:
- dept: 担当課（計画の所管課、係名、電話番号があれば）
- plan_summary: 対象計画の概要（名称・期間・主な施策を2〜3行）
- next_schedule: 次期計画の見込みスケジュール（予算要求時期、発注見込み時期、協議会/審議会の予定）。既に着手していればその事実（日付・URL）
- past_contract: 現行計画（または前回計画）の策定支援業務の発注方式・年度・受託者・金額（プロポーザル結果、入札結果、議会資料など。見つからなければ「不明」）
- related: 関連する動き（鉄道・バス路線の廃止/再編、デマンド交通、ゼロカーボン宣言、総合計画改定時期など営業トークに使えるもの）
- talking_points: 訪問時の切り口（2〜3点、事実に基づく）
- sources: 根拠URLの配列
出力: memos_<E|F>.json — 配列。各要素 {"pref","name","target_plan","plan_summary","dept","next_schedule","past_contract","related","talking_points","sources","note"}
共同計画（南秋地域=五城目町・八郎潟町・大潟村、福島県避難地域=県）は1件にまとめてよい。
